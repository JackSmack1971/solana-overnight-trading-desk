# Desk executable contracts

**Owns:** executable contract definition and review handoff; authority remains blueprint v2.6, especially §§2, 12–13, 17–18, 22. Read applicable root/scoped instructions and affected blueprint sections before changing files; `contracts/AGENTS.md` is applicable only when present.

1. Inspect current Git diff, prior contract records, source section, OD and acceptance identifiers. Preserve inherited IDs; a historical prefix is not an alternative specification. Determine whether `contracts/ACTIVE_RULES.json`, schemas, SQL and fixture map already exist; do not overwrite partially implemented work.
2. Author **one atomic active definition per rule** and index only explicitly authored records: current/original section, stable ID, supersession, decision/test links, units, predicate, time endpoint, null/UNKNOWN treatment, typed error and implementation status. A prose extraction is a proposal until reviewed; `ACTIVE_RULES.json` cannot override the blueprint.
3. For schema or state changes, cover money as atomic integer-string values, campaign/portfolio ownership, ordering, immutable terminal outcomes, the two-commit availability witness and crash windows (§6.4), generation/health watermarks (§6.5), retirement-before-buy (§4.9), event hashes, replay modes and historical cutoffs where affected (§§6, 10, 12, 14). Express accepted/forbidden transitions and independent fixture expectations, not just happy-path API shapes.
4. Check duplicate active IDs, missing/undefined OD-001–OD-049 or acceptance links, conflicting constants, unsupported enum/null paths, blueprint-version drift, fixture coverage and traceability across all active blueprint sections (§§13.2,22). Distinguish unimplemented contracts from semantic contradictions; never fabricate entries to make an index complete. Use existing repository validation tooling when actually present; if not, inspect those conditions explicitly and mark mechanical validation NOT_RUN. Include a negative fixture for every changed consequential rule. Do not weaken test claims to close coverage.
5. Request independent semantic review through `desk-review-gate` or an actually available independent reviewer, with unchanged blueprint passages and explicit counterexamples; do not assume a named subagent exists. Acceptance needs actual contract artifact(s), independent fixture mapping and review findings disposition. Stop dependent runtime implementation on CONTRACT_CONFLICT or unapproved policy; independent unaffected modules may proceed.

Return changed rule IDs/files, authoritative passage IDs, fixture/test mapping, actual verification receipts and blockers. Hand off approved executable contracts to `desk-implement-slice` with `baseline_ref`, `blueprint_hash`, `slice_id`, immutable rule/test IDs and review disposition; if `CONTRACT_CONFLICT`, stop dependent code only. Do not fabricate source commits, deployed compatibility or approval.
